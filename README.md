# LazyVim Dojo

A hands-on course for people who know their Vim motions but get lost in
everything LazyVim adds on top: the file tree, splits, buffers, pickers, LSP,
git hunks, the terminal and which-key.

It has two halves:

- **A web course** (`site/`): 12 short lessons. You type the real keys in the
  browser and it tells you what they would do. There's also a flashcard drill
  for building muscle memory and a searchable reference of every keymap.
- **A practice project** (`callsheet/`, created on first run): a small Lua
  project with deliberate problems (an unused variable, a missing field,
  uncommitted changes), so you can repeat each lesson in your real nvim with
  real LSP diagnostics, go-to-definition and rename.

Every key in the course was checked against a live dump of LazyVim's keymaps,
not just the docs.

## Requirements

- Neovim with [LazyVim](https://www.lazyvim.org/) and the
  `editor.neo-tree` extra (`:LazyExtras`, then `x` on `editor.neo-tree`)
- `lua_ls` (LazyVim installs it through Mason the first time you open a Lua file)
- `git`, and optionally `lua` to run the project and `lazygit` for the git lesson
- Any modern browser

## Use it

```sh
git clone https://github.com/edmooredop/lazyvim-dojo
cd lazyvim-dojo
./practice --site    # open the course
./practice           # open nvim on the practice project
./practice --reset   # put the practice project back to its starting state
./practice --keys    # re-dump keymaps from YOUR nvim so the course matches your config
```

The site is plain static files, so you can also just open `site/index.html`.
Progress is kept in your browser's local storage.

## Customising

- `site/lessons.js` holds the curriculum. Each step is `say` (explanation),
  `keys` (typed in the browser and checked against the keymap dump) or `nvim`
  (do it in the editor, then tick it off).
- `site/keymaps.js` is generated by `tools/dumpmaps.lua`. The shipped file comes
  from stock LazyVim plus the neo-tree extra. If your config remaps things, run
  `./practice --keys` and the course and reference will follow it.
- `seed/` is the practice project's starting state: `base/` is committed and
  `changes/` is left uncommitted for the git lessons. The `.env` key is fake.

## Limits

Browsers can't capture a few keys (notably `Ctrl-w`), so those are explained
instead of typed. Some browsers also reserve other Ctrl shortcuts, but none of
the ones the course uses.
